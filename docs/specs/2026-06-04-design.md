# claude-usage-bar — Design

- **Data:** 2026-06-04
- **Status:** Aprovado (aguardando revisão da spec)

## 1. Objetivo

Indicador de bandeja (system tray) para **Ubuntu/GNOME** que mostra, em tempo
real, as janelas de rate-limit do plano **Claude Code** (5h e 7d) com countdown
de reset. Reusa o token que o Claude CLI já guarda localmente — sem dashboard,
sem login extra.

Projeto independente, em Python. Foco: leve, nativo do GNOME, zero dependências
`pip`.

## 2. Escopo

**Inclui:**
- Janela de uso **5h** e **7d** do Claude.
- Barra superior do GNOME: **anel medidor colorido + texto fixo** `5h X%  7d Y%`
  (via `set_label`, sempre visível) + menu com o detalhe completo.
- Refresh automático a cada 5 minutos.

> Nota de evolução: a versão inicial mostrava **só o ícone** (detalhe no menu).
> Por pedido, passou a exibir também o texto das duas janelas fixo na barra
> (`AyatanaAppIndicator3.set_label`), como um monitor de RAM/CPU.

**NÃO inclui (decisões explícitas):**
- Outros providers (ex.: Codex/OpenAI). Só Claude.
- **Auto-refresh / escrita no arquivo de credenciais.** O app é *read-only*
  sobre `~/.claude/.credentials.json`. Renovar o token continua sendo
  responsabilidade do Claude CLI (abordagem "passiva").
- Empacotamento `.deb`/Flatpak, assinatura, distribuição.

## 3. Ambiente alvo (verificado nesta máquina)

| Item | Valor |
|---|---|
| OS | Ubuntu 26.04 LTS |
| Desktop | GNOME Shell 46, sessão **Wayland** |
| Tray | extensão `ubuntu-appindicators@ubuntu.com` instalada → StatusNotifierItem OK |
| Python | 3.13 |
| Token Claude | `~/.claude/.credentials.json` → `claudeAiOauth.accessToken` (+ `expiresAt` em ms) |
| Lifetime token | access token ~8h; existe `refreshToken` (não usado — modo passivo) |

## 4. Stack

- **Python 3** + **GTK 3** (`gi`) + **AyatanaAppIndicator3**.
- **HTTP:** `urllib.request` (stdlib) → **zero dependências pip**.
- **Desenho do ícone:** Cairo (via `gi`, já vem com GTK).
- **Dependências de sistema (apt):** `python3-gi`, `gir1.2-gtk-3.0`,
  `gir1.2-ayatanaappindicator3-0.1`.

## 6. Arquitetura e fluxo de dados

```
GLib.timeout_add_seconds(300) ─► schedule_refresh()
                                      │
                                      ▼
                          threading.Thread(target=probe)
                                      │  (rede fora da main loop)
                                      ▼
            credentials.read() ─► claude_probe.fetch() ─► Usage | ProbeError
                                      │
                                      ▼
                       GLib.idle_add(apply_result)   (volta p/ main thread)
                                      │
                          ┌───────────┴───────────┐
                          ▼                       ▼
                   icon.render(worst%)      rebuild Gtk.Menu
                   indicator.set_icon       indicator.set_menu
```

- Token **relido a cada ciclo** (sem cache) — pega renovação do CLI automaticamente.
- Primeiro refresh disparado no startup, antes de armar o timer.

## 7. Credenciais (read-only)

`credentials.read()`:
- Lê `~/.claude/.credentials.json`, parseia `claudeAiOauth`.
- Retorna `Credentials(access_token: str, expires_at_ms: float | None)`.
- Erros tipados (`CredentialsError`) com mensagem curta pt-BR: arquivo ausente,
  JSON malformado, sem `accessToken`.
- **Short-circuit de expiração:** se `expires_at_ms` existe e já passou (margem
  ~30s p/ clock skew), o probe não é feito — resultado já é `token expirado`
  (evita request garantidamente-401).

## 8. Probe do Claude

O token OAuth do Claude Code exige cabeçalhos específicos (mimetiza o CLI):

| Campo | Valor |
|---|---|
| endpoint | `POST https://api.anthropic.com/v1/messages` |
| `Authorization` | `Bearer <accessToken>` |
| `anthropic-version` | `2023-06-01` |
| `anthropic-beta` | `oauth-2025-04-20` |
| `User-Agent` | `claude-code/2.1.5` |
| modelo (body) | `claude-haiku-4-5-20251001` |
| body | `{"model":…, "max_tokens":1, "messages":[{"role":"user","content":"."}]}` |
| timeout | 20s |

É um request mínimo (`max_tokens:1`): o **corpo da resposta é ignorado**; só
interessam os headers de rate-limit (case-insensitive):
- `anthropic-ratelimit-unified-5h-utilization` / `-5h-reset`
- `anthropic-ratelimit-unified-7d-utilization` / `-7d-reset`

Resultado: `Usage(five_hour_pct, seven_day_pct, five_hour_reset_epoch, seven_day_reset_epoch)`.

**Separação testável:** `parse_response(status, headers)` é função pura (recebe
status + dict de headers), separada da chamada de rede `fetch()`. A lógica de
parsing é testada sem socket/mock.

## 9. Modelo de erro

| Erro | Origem | Texto no menu |
|---|---|---|
| `unauthorized` | HTTP 401/403, ou expiração detectada | `token expirado — rode 'claude' uma vez` |
| `http(code)` | status ≠ 2xx **e** sem headers | `HTTP <code>` |
| `no_headers` | 2xx mas sem headers de rate-limit | `sem headers de rate-limit` |
| `transport(msg)` | rede off, timeout, DNS | mensagem curta da exceção |
| `credentials(msg)` | arquivo/JSON de credencial | `<msg>` (ex.: `credencial não encontrada`) |

Os headers vêm mesmo em 200/400/429 → tentamos lê-los **antes** de tratar o
status como fatal (um 429 ainda informa o uso).

## 10. Funções puras — tabelas de caso (validar antes de codar)

### `parse_percent(raw: str | None) -> float`
Normaliza p/ 0…100. Valores ≤ 1 são tratados como fração.

| input | output | nota |
|---|---|---|
| `"0.41"` | `41.0` | fração |
| `"41"` | `41.0` | já em % |
| `"85.5"` | `85.5` | já em % |
| `"1"` | `100.0` | ≤1 → fração |
| `"0"` | `0.0` | |
| `""` / `"abc"` / `None` | `0.0` | inválido → 0 |

Invariante: saída sempre em `0…100` (clamp final).

### `reset_text(epoch: float | None) -> str`
Countdown legível a partir de epoch unix (s). `secs = epoch - now`.

| condição | output |
|---|---|
| `epoch is None` | `""` |
| `secs <= 0` | `"reset agora"` |
| `d > 0` | `"reset {d}d{h}h"` |
| `h > 0` (e `d==0`) | `"reset {h}h{m}m"` |
| senão | `"reset {m}m"` |

`d=secs//86400`, `h=(secs%86400)//3600`, `m=(secs%3600)//60`.
Casos: `now+90s → "reset 1m"`; `now+5000s → "reset 1h23m"`; `now+360000s → "reset 4d4h"`; `now-10 → "reset agora"`.

### `bar_unicode(pct: float, cells: int = 7) -> str`
Barra estética p/ o menu. `filled = round(clamp(pct,0,100)/100*cells)`.
Retorna `"█"*filled + "░"*(cells-filled)`.

| input | output (cells=7) |
|---|---|
| `0` | `░░░░░░░` |
| `41` | `███░░░░` |
| `100` | `███████` |

## 11. Ícone medidor (barra superior)

- **Desenho (Cairo):** medidor circular (anel/arco) ~22×22px. Ângulo preenchido
  proporcional ao **pior caso** = `max(5h%, 7d%)`.
- **Cor por limiar:** verde `<80`, laranja `≥80`, vermelho `≥95`.
- **Estados especiais:** cinza para *carregando* (sem dado) e para *erro/expirado*.
- **Aplicação:** renderiza PNG num diretório temporário próprio, registra-o via
  `set_icon_theme_path(dir)` uma vez; a cada update grava nome novo
  (`gauge-<contador>.png`) e chama `set_icon_full(nome, "")` — nome diferente
  força o painel a recarregar.
- **Risco a validar:** comportamento de `set_icon_full` + theme path sob
  ubuntu-appindicators/Wayland. Plano B: alternar entre dois nomes fixos.

## 12. Menu (o "popover")

`Gtk.Menu` (dbusmenu) com itens **de texto** (dbusmenu não suporta widgets ricos
de forma confiável; texto + barras unicode é robusto):

```
Uso do plano                         (insensitive, cabeçalho)
─────────────────────────
  5h  ▕███░░░░▏  41%   reset 2h13m   (insensitive)
  7d  ▕█░░░░░░▏  12%   reset 5d3h    (insensitive)
─────────────────────────
↻ Atualizar agora        (12:45:03)  (ação → refresh)
⏻ Sair                               (ação → quit)
```

- Em erro: linha única, ex.: `⚠ token expirado — rode 'claude' uma vez`.
- Sem tooltip de hover (o GNOME ignora tooltip de AppIndicator) — detalhe no menu.

## 13. Refresh / threading

- Intervalo: **300s** (`GLib.timeout_add_seconds`).
- Probe roda em `threading.Thread` (rede não bloqueia a UI).
- Atualização de UI sempre via `GLib.idle_add` (thread-safety do GTK).
- "Atualizar agora" dispara refresh fora de ciclo.

## 14. Instalação e autostart

- **`install.sh`:** `sudo apt install -y python3-gi gir1.2-gtk-3.0
  gir1.2-ayatanaappindicator3-0.1`; copia o projeto p/
  `~/.local/share/claude-usage-bar`; cria
  `~/.local/share/applications/claude-usage-bar.desktop`.
- **`autostart.sh on|off`:** escreve/remove
  `~/.config/autostart/claude-usage-bar.desktop`, apontando p/
  `python3 ~/.local/share/claude-usage-bar/main.py`.

## 15. Testes

- **unittest** (stdlib), sem rede:
  - `test_format.py` — tabelas da seção 10.
  - `test_probe_parse.py` — `parse_response` com headers presentes/ausentes,
    status 200/401/429/400, fração vs %.
  - `test_credentials.py` — JSON válido, sem `accessToken`, malformado, expiração.
- **Validação real (manual):** rodar contra as credenciais reais desta máquina e
  confirmar headers, ícone refletindo o uso e tratamento de expiração.
- TDD nas funções puras; `simulate-before-implement` aplicado às tabelas da seção 10.

## 16. Riscos / pontos a validar na implementação

1. `set_icon_full` + theme path forçando reload do ícone sob Wayland (seção 11).
2. Legibilidade do medidor a ~22px (arco vs anel vs preenchimento sólido).
3. Endpoint/headers do probe válidos (validação real).
4. dbusmenu renderiza barras unicode de forma aceitável na fonte do tema.
